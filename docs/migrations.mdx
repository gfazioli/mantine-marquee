## Upgrade guide

This page collects the **breaking changes** and **migration steps** for each major version of `@gfazioli/mantine-marquee`. If you are starting a new project, you can skip this page: everything here is about updating existing code from an older version.

New features that do not break anything are **not** listed here. See the [GitHub Releases](https://github.com/gfazioli/mantine-marquee/releases) page for the full changelog.

## v5

v5 makes `Marquee` a true drop-in for the `@mantine/core` Marquee: code written for core keeps its meaning after changing the import.

### Breaking changes in v5

- **`gap` tokens resolve through `theme.spacing`**, as in core, instead of the component's own scale. The default moves from `"xl"` to `"md"`, so a marquee without `gap` keeps its 16px with the default theme, and a theme with custom spacing now changes the marquee gap too. Numbers and CSS values (`gap={20}`, `gap="2rem"`) mean what they meant before.
- **The `--marquee-gap-xs` … `--marquee-gap-xl` CSS variables are gone.** `--marquee-gap` still holds the resolved gap.
- **`pauseOnHover` also pauses on keyboard focus**: while a link or button inside the marquee has `:focus-visible`, the loop stops. The pause is now pure CSS, and the hover area is the whole root, as in core.
- **`unstyled` now also removes the scroll styles** of the element holding the copies and of each copy, because they are the `content` and `group` selectors of the Styles API now. An `unstyled` marquee no longer animates by itself.

The same mapping applies to each breakpoint of a responsive `gap`:

```tsx
// v4
<Marquee gap={{ base: 'xs', md: 'xl' }} />

// v5, same sizes
<Marquee gap={{ base: 1, md: 'md' }} />
```

Numbers are converted to `rem`, so `gap={4}` is 4px at the default scale. If you overrode `--marquee-gap-md` (or another token variable) through `vars` or `styles`, set `--marquee-gap` instead, or change `theme.spacing`.
